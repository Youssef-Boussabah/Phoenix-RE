# @phoenix/evidence

Owner: unassigned (D-014 OPEN). Private M0 package. Requires Node ≥24.11.0.

`createEvidenceStore({ dataDir, readOnly? })` opens/migrates `phoenix.db` and returns `db`, `artifacts`, `repos`, `evidence`, and asynchronous `close()`. The only workspace dependency is contracts. No target execution, network access, subprocesses, tool dispatch or job runner exists here.

Repositories provide validated insertion/append, ID retrieval and bounded lists (default 100, maximum 5000). Lists order by ID with an exclusive ID cursor; event lists order by global sequence; finding history orders by revision. `evidence.list` returns the shared paginated typed contract and computes observation/finding staleness. Low-level repository lists return arrays; use the last ID to continue. No deletion or GC is implemented.

- `projects.create/insert/get/list`
- `targets.add/get/list/stale`: immutable manifests, local digest idempotence and supersession
- `repos.artifacts.register/insert/byHash/get/list`: metadata only; use `artifacts.put*` for byte-backed writes
- `jobs.create/insert/get/list/save`: initial state/version validation, optimistic updates, accepted state transitions, immutable job identity and terminal records. Create/state/finish lifecycle events are included automatically when not supplied. Supplied events and step writes commit atomically; inconsistent lifecycle events roll back. This is persistence, without scheduling or execution.
- `steps.insert/get/list/save`: step key uniqueness, bounded monotonic attempts and attempt compare-and-swap
- `events.append/list`: generated global sequence; replay of an identical event ID returns the original, conflicting replay fails
- `invocations.append/get/list`: validated request/envelope and optional job/step/cache provenance. `params_json` contains the validated request (including its params and limits), preserving the existing request contract without adding a column. Other columns remain query projections.
- `observations.insert/get/list`, `evidenceRefs.insert/get/list`, `findings.append/get/list/history`, `relations.append/get/list`

`db.transaction(fn)` accepts synchronous callbacks only, uses BEGIN IMMEDIATE and rolls back on exceptions; nested repository calls use SAVEPOINTs. Every operation checks owned transaction state before and after execution. SQLite auto-rollback poisons the active owner and all nested callbacks until the outer scope exits; later operations cannot fall through into autocommit. Commit/release validity is checked, and cleanup never releases nonexistent savepoints. Never dispatch asynchronous work in a transaction. The type checker rejects Promise-returning callbacks and runtime detection rejects thenables. SQLite and filesystem operations have separate commit boundaries.

`artifacts.putBytes/putStream` implement ArtifactWriter. Streams enforce a hard byte limit and hash/write one chunk at a time. Files are synchronized before publication. Atomic hard-link creation provides no-clobber publication on supported local filesystems, avoiding rename overwrite races; unsupported filesystems fail with STORAGE_ERROR. Transient Windows EPERM/EBUSY/EACCES publication/temporary-unlink failures retry at most ten times, with 10–100 ms backoff (≤850 ms total delay per operation). No platform behavior is inferred from mocked tests. Final blobs are read-only. Existing content is rehashed before deduplication succeeds. The first metadata row determines the returned artifact ID/media type for a digest.

`artifacts.verifyRegistered(artifactId)` synchronously rehashes registered content in 64 KiB chunks for atomic finding commits; it rejects missing, non-file, corrupted or incorrectly sized blobs. This verifies bytes at commit time, not their survival against later external mutation. `artifacts.open(sha256)` and `read(artifactId)` stream bytes; fully consume or close iterators to release handles. Ordinary reads detect missing/non-file blobs. Explicit `fingerprint` verifies actual hashes and recorded sizes; `reconcile(page)` verifies a bounded page of metadata records without deleting or rewriting anything. Store shutdown stops accepting puts and drains in-flight puts before closing SQLite. Consumers must release read iterators before removing their data directory.

Recovery: failed streams remove their stage. A process crash may leave an unreferenced temp file, or a valid published blob without a database row. No automatic deletion occurs. Re-uploading identical bytes verifies/reuses an orphan and registers metadata; re-upload can also restore a missing blob for an existing row. Corrupt blobs fail closed and are never overwritten automatically. Reconciliation reports missing/corrupt registered blobs; it does not enumerate all unregistered blobs. A durable DB row does not prove blob durability after arbitrary power loss. WAL and fsync improve recovery but do not provide distributed atomicity, hostile-filesystem protection or backup of artifacts.

Target attachments are checked inside the target transaction, before idempotence or supersession: file artifacts require matching SHA-256/digest and supplied size; complete file snapshots require an artifact. Inventory attachments require a directory target and registered `application/vnd.phoenix.inventory+json` artifact. Reference targets can retain matching snapshots, and incomplete references can omit digest/artifact information. No mismatched metadata is repaired silently.

Every finding citation, including citations in hypotheses, must associate its artifact with the finding target through that target's snapshot/inventory or an observation's dataArtifactId. A supplied observation ID must belong to that target and identify the cited output or interpret the target's own snapshot/inventory. A reference row alone cannot establish association. Each supporting artifact is synchronously fingerprinted within the revision transaction. Hypotheses may still have no citations; factual statuses must have supporting citations.

ADR-0009 privacy: raw authoritative `url` and HTTP(S) `uri` strings are strictly validated before schema normalization and reduced to origin/path. Source-derived text is untrusted content, not an asserted URL: best-effort redaction preserves safe text and prefixes, normalizes unambiguous URLs, and replaces malformed/ambiguous URL suffixes with `[URL_REDACTED]`. Quotes, markup, Unicode whitespace and controls never terminate a token in a way that retains a credential suffix. Once access syntax appears, the complete remaining suffix is treated as access context. This deliberately can redact extra trailing source text. Metadata-key collisions receive deterministic numeric suffixes. Filesystem localPath identity is preserved. URL_ACCESS_CONTEXT_REMOVED explains that sanitized identities are not equivalent retrievable sources. URL manifests reject localPath and explicit supersession. Their source key remains `intake:<target-id>`; separate query-dependent intakes never merge. Errors omit raw input/SQLite text. This is not a universal secret detector for paths or arbitrary free text.

Evidence queries use separate indexed UNION ALL arms for snapshots, inventories, primary/candidate jobs and observation/finding associations. Final DISTINCT removes overlapping associations before deterministic pagination. The unshipped initial migration now includes artifact/target/job association indexes. Databases created with the earlier development checksum fail with MIGRATION_CHECKSUM_MISMATCH; explicitly initialize a separate disposable development store rather than deleting user data. After shipment, schema changes require a new forward migration.

Raw `db` access is for trusted migrations/diagnostics and transaction composition; repositories define the validated persistence boundary. Callers must not bypass it to persist unvalidated documents. Each store requires a trusted, exclusively user-managed local data directory; network filesystems and adversarial path replacement are outside M0 guarantees.

See [WP4 hardening results](../../docs/WP4_HARDENING_RESULTS.md) for current verification and pending platform gates; [initial WP4 results](../../docs/WP4_RESULTS.md) are historical.

Incomplete local manifests retain their actual unknown/truncated metadata and absent digest. Local sources require absolute paths; idempotence by digest applies only when both digests exist. A later intake for the same local source with an unknown or different digest records a new superseding manifest, conservatively marking prior observations stale.
