# @phoenix/toolkit

Owner: unassigned (D-014 OPEN). Priority: P0. WP2 provides platform services for future analysis providers; no format parsers, target classifier, provider registry or dispatcher exists yet.

The package has one public entry point and one runtime workspace dependency, `@phoenix/contracts` (which depends on Zod). Only `src/platform/process.ts` owns process spawning. It performs no work at import time except constructing the ID generator. Filesystem inspection never executes an imported target.

Public services:

- `detectHost(version, options?)`, `mapCpuArch`, `defaultDataDir`: Windows/macOS/Linux, CPU, WSL, best-effort translation and per-user application storage. `PHOENIX_HOME` must be absolute. Relative XDG locations are ignored. Detection reads kernel metadata; a Rosetta sysctl probe runs only if the caller supplies an authorized runner. Unknown translation remains absent rather than fabricated.
- `toPosixRel`, `nfc`, `resolveRelativePath`, `assertContained`, `isPathWithin`: canonical paths, component-based native/drive containment, existing-path checks and no link/junction traversal below the root. Native paths normalize to NFC; serialized paths must already satisfy the contracts. Windows native paths additionally reject device names (including conservative COM0/LPT0 and CONIN$/CONOUT$ handling), alternate streams, trailing dots/spaces and forbidden characters. Fully qualified storage, executable, cwd and Windows PATH entries require a drive or UNC share; drive-less rooted paths are rejected. POSIX backslash filenames are unsupported by the committed serialized path contract and cause an explicit error. Canonical component lookup resolves native NFD names and rejects ambiguous NFC identities, with a 50,000-name cap per component. Case is preserved; no global case-folding assumption is made.
- `openRegularFile`, `readFileStream`: read-only regular handles, no final symlinks or special files, POSIX no-follow/nonblocking open, identity/size/mtime/ctime verification. Range limit is 1 MiB; stream chunks are 64 KiB. Reads past EOF return the available suffix or empty bytes. Stream completion, early return, failure and cancellation close the handle. An explicitly opened handle belongs to the caller, which must close it in `finally`. Call `resolveRelativePath` first for directory-relative access; a standalone file open does not validate every ancestor.
- `newId(prefix)`, `createIdGenerator`: branded UUIDv7-derived contract IDs, 48-bit millisecond timestamp, version 7 and RFC variant. A per-process 12-bit sequence gives sortable same-millisecond IDs. Clock rollback holds the previous timestamp; sequence overflow advances logical time. Randomness remains in the 62-bit tail. These are identifiers, not authentication tokens.
- `hashStream`, `hashFileTo`: incremental SHA-256, optional byte cap/AbortSignal and awaited tee sink. Snapshot writers can hash and copy identical bytes in one pass. Sink failure closes the source. No CAS storage is implemented.
- `hashDirectory`: iterative bounded walk and the exact M0 plan §5.4 `phoenix-tree-sha256-v1` byte stream. Defaults: 50,000 visited entries, 4 GiB file bytes, exclusion `.git`. Exclusions are literal basenames (any depth) or root-relative paths (and their subtree), sorted/deduplicated in the header, and reported even if unmatched. Entries sort by NFC UTF-8 bytes. Links are recorded without traversal; their UTF-8 payload bytes are hashed without normalization. Special entries receive `O` records without opening. Invalid UTF-8, unsupported paths or normalization collisions reject the operation. Count/byte truncation returns entries plus `INVENTORY_TRUNCATED`, with **no digest**. `encodeTreeRecord` only encodes the approved tuple format; filesystem path validation happens in the walk.
- `findExecutable`, `executableCandidates`, `isWindowsStoreAlias`: PATH/PATHEXT lookup; ignores empty/relative PATH components, inaccessible/nonregular/empty candidates and Windows Store Python aliases. Lookup checks OS executable permission on POSIX. This is discovery, not binary-format validation or a guarantee that a program will launch. `discoverVersion` requires a caller-supplied runner; stdout and stderr are bounded and returned for tool-specific parsing.
- `createProcessRunner`: caller explicitly authorizes a named workflow. Default-denied policies cannot spawn. Executable/cwd must be absolute; arguments remain arrays with `shell: false`. Batch scripts are refused, including trailing-dot/space and alternate-stream aliases. Inherited environment is filtered through `PROCESS_ENV_ALLOWLIST`; unsupported requested overrides are rejected with INVALID_REQUEST rather than silently ignored. NODE_OPTIONS, Python startup variables and arbitrary variables remain excluded. A SystemRoot override must match the host. Synchronous/asynchronous spawn errors are normalized using a safe OS error code and phase only; arguments and environment values are omitted. Timeouts are 1 ms–1 hour; the combined stdout/stderr cap is 0–64 MiB. Cancellation, timeout and overflow reject with sanitized PhoenixError; a nonzero normal exit returns its actual exit code. The toolkit result adds the OS signal to the shared result structurally without changing contracts. Raw arguments and output are never logged automatically.
- `createLogger`, `sanitizeLogText`, `serializeLogError`: typed diagnostic levels, bounded redacted fields, sanitized errors and one JSON record per line to stderr by default. Default event limit is 16 KiB (configurable 256 bytes–1 MiB); oversized events become small truncation records. ANSI/OSC/control and bidi injection is removed/escaped. Credentials, private keys, common home/UNC paths and sensitive payload fields are masked. The current home directory is always masked alongside up to 32 custom `privatePaths`; patterns are compiled once per logger. ANSI/OSC sequences and invisible/control separators are neutralized before matching; removed controls are represented by bounded escaped markers when redaction changes the text. Credentials are also masked before joining whitespace controls. Keys include credentials/passphrase/auth/pwd, including camel-case auth fields; author metadata is retained. Plain diagnostic field objects retain at most 32 supplied top-level fields plus an omission marker, 256-character keys, and per-field budgets of 256 child properties, 8192 input characters and 4096 serialized bytes, plus shared JSON depth/size caps. Invalid/oversized/accessor fields become markers while valid siblings survive. Text input over 16,384 characters becomes an omission marker; returned text caps at 8192 characters. Event-byte overflow still emits a small truncation record. Error details use the same credential and control redaction. Callers must supply diagnostic metadata rather than raw source/target payloads. Pattern redaction is not a universal secret classifier. Custom sinks own their I/O/backpressure handling; stderr writes use Node's normal buffering.

```ts
import { createProcessRunner, findExecutable } from '@phoenix/toolkit';

// Construct only after workflow approval; never infer permission from target compatibility.
const process = createProcessRunner({ allowExecution: true, workflow: 'approved tool version probe' });
const file = await findExecutable('git');
if (file) {
  const result = await process.runProcess({
    file,
    args: ['--version'],
    cwd: '/absolute/caller-selected/workspace', // supply a native absolute path on your host
    timeoutMs: 5000,
    maxOutputBytes: 8192,
    signal: AbortSignal.timeout(6000),
  });
}
```

Filesystem verification reduces races but cannot make a mutable namespace atomic. Metadata checks can miss same-size/same-timestamp mutations on coarse filesystems, deliberately restored metadata, writes after the final check or mutations inside excluded subtrees. They are not cryptographic change detection. Regular-file hard links are allowed: an external alias can modify the same inode, and read-only handles do not prevent such writes. A later hash verifies only the bytes actually read; the namespace still is not an atomic snapshot. Read-only snapshots or OS isolation are required for hostile concurrent writers. A digest describes the included inventory, with exclusions encoded explicitly; it is not a claim about excluded content.

POSIX process cleanup kills a detached process group, including ordinary descendants, even when the parent exits first. A descendant can escape by starting another session. Windows uses the host's absolute System32 `taskkill.exe /T /F /PID` only for an observed live child during timeout, cancellation or output overflow. Observed exit/close disables PID-based termination; normal exit never launches taskkill. First failure wins and cleanup starts once. Windows cannot reliably track descendants after parent exit; reliable containment requires a future Job Object-based provider. PID-based checks cannot eliminate every native exit/reuse race. The execution timer stops at parent exit. A separate 2.5-second output-drain deadline closes retained pipes: normal parent exit with retained pipes reports PROVIDER_FAILED with details.phase=output-drain, while an earlier timeout/cancellation/output limit retains its primary reason. TIMEOUT with phase=execution refers to running execution. This is not a Windows Job Object. No runner is a sandbox, CPU/memory limit or network policy enforcer. Workflow authorization is a caller policy gate, not a capability security boundary.

Test surface: real temporary paths/streams, symlinks/junctions, POSIX FIFO/socket/device rejection, actual Node child processes and descendant PIDs/heartbeats, hash vectors, Unicode/order/collision/exclusion/truncation records and bounded logs. Windows skips POSIX-only primitives, signal reporting and post-parent-exit process-group semantics; missing symlink privilege and filesystem normalization/case limitations have explicit reasons.
